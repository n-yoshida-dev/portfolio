## 何を解いているか

独学では「分かったつもり」を自分で見抜けません。
このシステムは、**学習の結果を根拠付きで記録し、根拠がなければ理解度を上げない**ことを仕組みで強制します。

## 流れ

```
学習セッション（Claude Code。1 セッション = 1 モジュール）
  ↓ セッション終了時に AI が学習ログを書く（学習者に書かせない）
学習ログ（study：非公開リポジトリ）
  ↓ 根拠になるもの：確認問題の結果 / 自分の言葉での説明 / 実装したコミット / 記事
evidence（根拠）
  ↓ 判定（今は手動の台帳、将来は skill-matrix が AI 判定 + 検証ルールで自動化）
judgment（どの項目にどの程度の理解が示されたか）
  ↓
verified skill（5 段階の習熟度 + 根拠 + 次の確認方法）
  ↓ 通らなかった確認問題は弱点として起票
weakness（誤解のパターン。7 日後・30 日後に再確認）
  ↓
next action（次のセッションで最初にやること）
```

## 守っているルール

- **「説明済み（質問が出なかった）」は理解の証明ではない**。台帳では「説明済み・理解未確認」として扱い、レベル 1 にもしない
- **昇格には根拠が要る**。確認問題への回答、自分の言葉での説明、ドリル結果、実装の実績。自己申告は「自己申告」と明記する
- **AI が書いたコードは習熟度の根拠にしない**。AI に任せた部分は「任せた」と記録する
- **同じ誤解が 3 回出たら弱点として起票する**。1 回目は事故、3 回目は構造の問題
- **学習時間より完成物を評価する**。同時に学ぶ技術の数ではなく、統合できた量で見る

## 使っているもの

- **学習の型**：読む → 追う → 説明する → 書く の順。目標は「言える / 追える / 書ける / 直せる / 選べる」で書く
- **Claude Code のスキル**：セッション開始（`/kickoff`）、ヒント段階（`/hint`）、デバッグの誘導（`/debug-coach`）、確認問題（`/study-drill`）、振り返り（`/reflect`）、学習ログ生成（`/study-log`）
- **教え方のルール**：1 メッセージ 1 概念、新出語は 3 つまで、専門用語は初出時に「何のためにそうするのか」を添える
- **横断の習熟度台帳**：技術 × 習熟度 × 根拠 × 次の確認方法。[Skills](/skills) ページはこの台帳から公開可能な部分を手で抜き出したもの
- **skill-matrix**：この台帳を自動化するプロジェクト。ロードマップを固定のマスタにし、AI の判定を CLI と CI で検証する（[Projects](/projects/skill-matrix)）

## 2 つの学習レーン

| レーン | 目的 | AI の関わり |
|---|---|---|
| OrgFlow（Java / Spring Boot） | 自分で考え、設計し、実装する主戦場 | 相談相手・レビュー役。コード生成は使わない |
| AI Dev Journey（React / Supabase） | AI エージェントに実装を任せ、自分は判断・レビューをする訓練 | 実装担当。自分は要件・レビュー・検証 |

OrgFlow の時間は削らない、という優先順位を先に決めています。
