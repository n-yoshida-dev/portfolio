## 解きたい課題

学習を続けていても「どこまで理解できているか」が自分で分かりません。
ロードマップにチェックを付けるだけでは「読んだ」と「理解した」の区別がつかず、忘れた分も反映されません。

そこで、**ロードマップを固定のマスタにし、自由記述の学習ログを AI に読ませて理解度を判定させます。**
人間は「今日やったこと・理解したこと」を書くだけで、理解度・次にやることの更新は仕組みが行います。

## 仕組み（v1：自分専用）

```
学習ログ（非公開リポジトリ）
  ↓ AI が指示書（prompts/judge.md）を読んで判定
data/judgments/  ← 1 回の判定 = 1 ファイル。追記のみ。根拠の出どころ（evidenceRef）を指す
  ↓ Go の CLI が検証ルールで検査し、再計算
data/state.json  ← 項目ごとの理解度（導出値）
  ↓
静的サイト（GitHub Pages）← 理解度マトリクス、学習パス、次にやること Top N
```

- 理解度は 5 段階（基礎理解を確認 / 自分で説明可能 / ガイド付き実装 / 自力実装・レビュー / 別文脈へ応用）
- 段階とは別に「根拠の種類が弱い」状態（学習中 / 説明済み・理解未確認 / 自己申告のみ）を持つ
- 時間経過で自動的に下げない。代わりに最終根拠日を持ち、鮮度として表示する
- 学習ログの本文はこのリポジトリに置かず、判定ファイルは「どのログを根拠にしたか」だけを指す。これにより判定データを公開できる

## 判断したこと

- **2026-09-23 に「公開する Web サービス」から「自分専用のツール」へ絞り込んだ。**
  着手から 6 週間で実装タスクは 24 件進んだが画面が 0 件で、当初の目的である可視化を一度も試せていなかった。
  ログイン・DB・非同期ジョブなど「他人に使わせる」ための実装は消さずに v2 へ棚上げした
- 判定は AI に任せるが、そのまま信用せず CLI の検証ルールと CI で二重に検査する。人間は `git diff` で判定の中身を見てからコミットする
- ロードマップ JSON は fork を前提にした形にしておき、後で他人に配れるようにしている（v1.5 でテンプレート配布を検討中）
