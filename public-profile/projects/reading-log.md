## 何か

本の書誌情報・進捗・メモ・感想・読了後のアクションを、1 冊 1 Markdown ファイルで管理するリポジトリです。
アプリを作ったのではなく、**GitHub と ChatGPT を組み合わせて「仕組み」だけを作りました。**

## 使い方

- **追加**：読みたい本は、ChatGPT の読書管理プロジェクトで追加を頼む。AI が Markdown を書いて GitHub に反映する
- **閲覧**：読書状況は、Markdown の更新に合わせて自動で作り直される GitHub Pages（Jekyll）で見る
- **週次レビュー**：毎週 ChatGPT の定期タスクが読む順番を決め直し、次に読む 1 冊を提案する（下の節）

## 週次レビュー（次に読む 1 冊を決め直す）

毎週 ChatGPT の定期タスクが、次の順で動きます（2026-10-04 から）。

1. **読書記録を読む**：全冊の記録・前回のレビュー・未処理の受け箱（inbox）を読み、受け箱の中身を対応する本へまとめる
2. **今の優先課題をつかむ**：自分の長期コンテキスト（非公開。[Personal AI Context System](/systems/personal-ai-context)）と、直近 7 日の ChatGPT との会話を読む。
   長期コンテキストは読むだけで、この処理では書き換えない
3. **全冊を評価し直す**：未読・読書中・一時停止中の本を、目標への効果、進行中の課題への直結度、読みかけを終える価値、今週使える時間、
   前の本のやり残したアクション、読む時期、似たテーマの重複といった観点で毎週見直す。順位を変えたら理由を、変えなかったら維持した理由を書く
4. **公開の読書記録に書く**：週次レビューに、次に読む 1 冊（必要なら代わりの 1 冊）・上位 3 冊・順位を変えた理由・今週やる小さな一歩を書き、読む順番を更新する

## 特徴

- **正本は GitHub**。ChatGPT のプロジェクトや各 AI のメモリに重要情報を残さない
- **非公開の判断材料を、公開の記録に書き写さない**。週次レビューの理由は「今の資格学習」のような一般的な言い方にとどめ、会話や非公開ファイルの中身を引用しない
- **AI の提案と本人の判断を分ける**。拾い読み・一時停止・中止などのステータスの変更は「AI 提案」と書き、本人が決めるまで確定しない。情報が足りないときは推測で埋めない
- **全 AI 共通のルール（AI_RULES.md）**。書誌情報を推測で確定しない、本人の感想を勝手に要約しない、本文の長い引用を残さない、など
- **完読を絶対視しない**。ステータスに `skimmed`（拾い読みで完了）と `abandoned`（中止）を正常な完了として持つ。同時に読むのは 2 冊まで
- **アクションは 1〜3 件に絞る**。読了後の行動を期限・完了条件付きで残す

## 判断したこと

- Notion や Obsidian に重複保存しない。将来使うとしても GitHub を一次情報にする
- ブランチ・PR は使わない。ChatGPT が `main` に直接コミットするため、作業前の `git pull` をルールにした
- 公開リポジトリなので、個人情報・勤務先の情報・書籍本文の長い引用は記録しない
- 読む順番の判断には自分の事情を使うが、それを記録する場所は非公開の長期コンテキストに分け、公開側には判断の結果と一般化した理由だけを置く
