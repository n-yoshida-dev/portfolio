## 狙い

開いた直後の 1 画面を「表紙」にし、置くのは名前・一言・要点 3 行・目次だけにする。カードや図などの本文は表紙の下から始める。
目次は本の目次の形にし、各節にどれだけ中身があるか（プロジェクト 12 件・記事 21 本など）を、数と小さな印で添える。本文を読まなくても、何がどれだけあるかが分かるようにする。
色・線・書体は今のままにして、大きな名前と余白と細い線で整える。動きは、開いたときに線が引かれて印が順に並ぶ 1 回だけにする（約 1.6 秒）。

## 部分ごとの案

- 構成：トップは 1 枚のページのまま。先頭に横幅いっぱいの表紙（画面 1 枚分）を足し、左の固定目次は表紙の下の 7 節の横にだけ出す（表紙を過ぎると左に貼り付く）
- 最初の画面に置くもの（1280×800）：左の列に、上から小さな行（Portfolio・最終確認日）→ 名前 → 一言 → 要点 3 行（小見出し + 太字の一文）→ 外部リンク（GitHub・Qiita・llms.txt）。右の列に目次 7 行（番号・節の名前・短い説明・中身の量を表す印・数）。右下に Ask AI ボタン
- 最初の画面に置くもの（375×812）：名前 → 一言 → 要点 3 行 → 目次 7 行（印は説明の行の右）→ 外部リンク →（下端に）小さな行（Portfolio・最終確認日）。右下に Ask AI ボタン
- 見た目：名前だけを今の 1.75rem から最大 3.4rem に大きくし、PC の表紙は画面の高さいっぱいに余白を取って中身を上下の中央に置く。要点は 3 列をやめ、細い線で区切った縦の 3 行にした。目次も細い線で区切った行にした。地色・影・新しい色は足していない
- 動き：開いたとき 1 回だけ。名前・一言・要点が下から 6px 浮き上がって現れ、要点と目次の区切り線が左から右へ引かれ、目次の印が 1 つずつ順に現れる（約 1.6 秒で終わる。CSS だけ）。目次の行にマウスを乗せると、その行の印が文字色に変わる。目次のリンクで節へ移るときは滑らかにスクロールする。reduce のときはどれも動かない
- 今の 7 節：表紙の下に、今と同じ順・同じ見せ方で 7 節を並べる。About 節は名前と一言を表紙に移したので、見出し「About」を見せ、要点 3 列（補足つき）と外部リンクのカード 3 つを置く。ほかの 6 節は今のまま
- 目次（PC の左・375px の上部）：PC の左の固定目次は中身を変えず、表紙の下から出す。375px の上部の横並びの目次はやめ、表紙の目次（縦に 7 行。番号・説明・数つき）で全項目を出す
- 右下の Ask AI ボタン：今のまま

## 変える決まり

- 「構成は 1 枚のページ + 左の固定目次」：1 枚のページは保つが、先頭に横幅いっぱいの表紙を足す。PC の左の固定目次は表紙の間は出さず、表紙の下からだけ出す
- 「トップの最初の 1 画面に、名前 + 一言 + 要点 3 行 + 目次が入る」：入るものは同じ。ただし要点 3 行は小見出しと太字の一文だけにし、薄い文字の補足は表紙の下の About 節に回す。最初の画面の目次は、左の固定目次ではなく表紙の中の目次にする
- 「About：要点を 3 列にし、各列を小見出し → 太字の見出し → 薄い文字の補足で積む」（2026-10-03）：表紙では補足を省いて縦の 3 行にする。表紙の下の About 節では今の 3 列のまま
- 「375px 幅では目次の全項目を上部に横並びで出す」：横並びではなく、表紙の中に縦の 7 行で全項目を出す（ボタンで隠さない点は同じ）。今の上部の見出し（名前・横並びの目次・リンク）は 375px では出さない
- 「本文幅は最大 52rem（左の目次 16rem を除く）」：表紙だけは左の目次が無いので、中身の幅を最大 68rem（左の目次 16rem と本文 52rem を足した幅）にする。表紙の下の 7 節は今のまま 52rem
- PLAN.md「やらないこと」のアニメーション：開いたとき 1 回だけの短い動き（線を引く・印を順に出す・6px 浮き上がる。約 1.6 秒。CSS だけ）と、目次のリンクで移るときの滑らかなスクロールを許す。どちらも reduce のときは出さない

## あなたが判断したこと

- 表紙の要点は補足を省いて見出しだけにし、補足は About 節に残した。そのため要点の見出しの文は、表紙と About 節で 2 回出る。最初の画面を軽くすることを優先した
- 目次の印は線のアイコンではなく、Articles の図と同じ「印 1 つ = 1 件」の小さな図として扱った。Projects の 12 は今の「4 / 12 件」の 12。Articles の 5 つのかたまりは連載ごとの本数（2・2・5・8・4。index.html の図と同じ）。Skills の 3 つの枠のうち破線は「理解確認済み・学習中」（下の Skills のカードと同じ書き分け）。Journey の 4 つの点は今の年表の 4 つの時期
- 印は青にせず、薄い文字の色にした。目次の行はまるごとリンクで、青はリンク専用だから。年表の点を青にする例外は Journey 節の中だけとした
- 目次の節の名前は青にせず、文字色の太字にした（今の左の目次のリンクと同じ扱い）
- About と Ask AI の行は数えるものが無いので、印と数を付けなかった
- 目次のリンク先は、詳しい版のページ（/projects など）ではなく、このページの各節（#projects など）にした。詳しい版へは各節の「すべて →」のリンクで行く（今と同じ）
- 375px では、外部リンクと「Portfolio・最終確認日」の行を目次の後ろへ回した。名前・一言・要点・目次の 7 行を 1 画面に収めるため
- 「最終確認日: 2026-10-03」は今のページの末尾から表紙へ移し、末尾からは消した。同じ日付を 2 か所に置かないため
- PC で表紙の間に左の固定目次を出さないのは、表紙の目次と目次が 2 つ並ばないようにするため。貼り付きは CSS の sticky だけで作り、JavaScript は今の目次のスクロール監視のまま（写して入れてある）
- PC の表紙の高さは画面の高さ（100svh）にした。最初の画面に Projects のカードがのぞかず、表紙だけが見える。下に続くことは目次とスクロールバーで分かるので、「下へ」の矢印などは足していない
- 書体は今の `--font-sans` / `--font-mono` だけを使った。名前の文字の太さも今の見出しと同じ 600 のまま
- 確かめた幅と配色：Playwright（Chromium）で 1280×800 と 375×812（ほかに 1440×900・1024×768・800×900・360×740）を、ライト・ダークの両方、開いて 4 秒後と reduce の両方で撮って確かめた。どの幅も横スクロールしない（動きの途中も 0.1 秒おきに測った）。4 秒後の姿と reduce の姿は画素まで同じ（動きが終わった後は CSS の値を持ち続けない書き方にしたため）
- 最初の画面の文字数（空白を除いて、画面にかかっている文字を数えた。右下のボタンを含む）は、1280×800 で 306 字、375×812 で 306 字だった。今の 701 字・372 字とは数え方が近いが、まったく同じではない
