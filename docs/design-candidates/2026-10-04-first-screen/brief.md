# ブリーフ：ポートフォリオの最初の画面の見せ方

このブリーフは同じ内容で複数の作り手に渡しています。お互いの案は見えません。あなたの案を 1 つだけ作ってください。

## 1. このサイトは何か

Naoki Yoshida の個人ポートフォリオサイト（公開中。Astro の静的サイト、素の CSS 1 ファイル）。
自作アプリの一覧と、AI・GitHub・自作ツールを組み合わせた開発・学習の仕組みを公開している。
今のトップ（`/`）は 1 枚のページに 7 節（About / Projects / Systems / Skills / Journey / Articles / Ask AI）を縦に並べ、左の固定目次で節へ移動する。
各節は短い版で、詳しい版は各ページ（/projects、/systems、/skills、/journey、/articles、/ask）にあり、「すべて →」などのリンクで行く。
About だけは詳しい HTML ページが無く、本文は Markdown 版（/profile.md）にだけある。
サイトを開いた人が最初に見るのはこのトップ。

### 誰のためのものか（サイトの計画書 PLAN.md の原文）

1. **転職の選考で見る人**：短時間で「何の人か」「何を作ったか」「どう開発しているか」を把握したい
2. **AI**：訪問者の ChatGPT / Claude / Gemini が、私について根拠付きで答えられるようにする（`/llms.txt`、Markdown 版、Ask AI）
3. **自分**：分散した成果物の索引。将来は skill-matrix から Skills を自動生成する土台

## 2. 頼みたいこと

サイトを開いたときに最初に出てくるページ（今のトップ `/`）の見せ方を変える案を 1 つ作ってください。見本で作り込むのは、そのうち開いた直後に見える範囲（5 の 1）。

サイトの持ち主が言ったこと（原文の前半。2026-10-03。後半は意見を求める問いと、このコンペの進め方の話）：

> あと、なんかずーっと引っかかっていたんだけど、今見ているトップ画面って、最初に開いたら出てくるページだよね？
> なんか、最初に開いたら出てくるページとして、いきなり情報量多くない？って思った。本当のトップページは情報量少なく、それでいておしゃれで革新的な方が、
> ファーストインプレッションがいいのかな？と思った。

見た目の枠について、持ち主が言ったこと（原文。2026-10-03）：

> 派手な見た目はやらないってのは同様です。ただ、シンプルなアニメーションとか、一部だけなら緩和しようかな。
> グラデーション・光るカード・3D・ロゴの羅列、のようなイケイケなSaaSみたいなのはちょっと私のイメージと違うかな。

変えてよい範囲：

- 最初に出てくるページに何を置くか、どう見せるか（とくに開いた直後に見える範囲）
- トップの構成（下の 3 の「1 枚のページ + 左の固定目次」）を変えてもよい。変えるなら、今の 7 節の内容がどこから読めるようになるかも示す

対象外（別のタスクで扱う）：

- 文面（言葉）の直し。言葉を短くする・選ぶ・並べ替えるのはかまわないが、事実・数字・実績を足さない
- 右下の追従ボタン「Ask AI about this portfolio」を押したときの動き。ボタンは今のまま描いてよい（消す・動かすなら、その判断を `aim.md` に書く）


## 3. 今の決まり（変えてもよいが、変えるなら明示する）

次の決まりは、これまで持ち主と合意して決めたもの。今回のタスクの完了条件（調整役の Claude がタスク一覧に書いた言葉）には「PLAN・SPEC §4 や 2026-09-27 の判断を変えるならその変更も含む」とあり、変えることは禁止されていない。
変える案なら、どれをどう変えるかを `aim.md` の「変える決まり」に書くこと。変えられない枠は 6 にある。

- 構成は「1 枚のページ + 左の固定目次」（2026-09-27）。この形に決めたときの持ち主の発言は、それまでのサイトへの不満「どこに何が書いてあるか構造として分かりづらい。上から読まないと分からない」と、
  左の目次について「タブは 1 枚のページで目次切り替えのような形でもよい」「実際にページを変えるのもよい」
- PLAN.md「やらないこと」：派手な見た目（グラデーション、光るカード、3D、アニメーション、ロゴの羅列）。
  薄枠のカードと左の固定目次は 2026-09-27 に、トップの汎用の線アイコン（ロゴではない）と記事の連載 × 公開月の図は 2026-10-03 に許容した。
  2 の持ち主の発言のとおり、緩めてよいのはシンプルなアニメーションなど一部だけ（ほかは 6 のとおり）
- 色は文字・薄い文字・線・リンク・背景（地色 `--bg-subtle` を含む）の 5 系統。ダークモードは OS 設定に追従
- 青はリンク専用（例外：Journey の年表の点は青）。ボタンは青を使わず文字色で描く。塗るのは主なボタンと右下の追従ボタンだけ。ボタンの角は 4px（カードは 8px。`input/site/global.css` のとおり）
- 一覧は薄枠のカード（地色 `--bg-subtle`、線 `--line`。PC 2 列〔例外：About の要点とリンクカードは PC 3 列〕、375px で 1 列）。影は使わない
- トップの About・Skills・Journey・Articles の見せ方は、2026-10-03 に持ち主が見本 3 案から節ごとに選んだもの（About：要点を 3 列にし、各列を「小見出し → 太字の見出し → 薄い文字の補足」で積む。
  外部リンクはアイコン付きのカード 3 列。Skills：区分ごとのカード。Journey：横の年表。Articles：連載 × 公開月の図）。線のアイコンは About のリンクと Skills の区分見出しにだけ使う
- トップの最初の 1 画面に、名前 + 一言 + 要点 3 行 + 目次が入る
- 375px 幅では目次の全項目を上部に横並びで出す（ボタンで隠さない）
- JavaScript は Ask AI のコピーと目次のスクロール監視だけ。ライブラリを増やさない
- 本文幅は最大 52rem（左の目次 16rem を除く）、モバイルは左右 16px の余白。横スクロールさせない
- HTML は人間向けに短く、Markdown 版・llms.txt は AI 向けに詳しく

## 5. 作るもの（あなたの作業フォルダの直下に置く）

1. `mockup.html`：案を描いた見本 1 枚
   - 1 ファイルで完結させる（CSS と JavaScript は中に書く。外部の画像・フォント・スクリプトを読まない。絵が要るならインライン SVG か CSS で描く。
     書体は今の `--font-sans` / `--font-mono` の並びか、総称〔serif・sans-serif・monospace〕だけを使い、特定の端末にしか無い書体の名前を書かない）
   - 最初の画面（1280×800 と 375×812 で開いた直後に見える範囲）を作り込む
   - その下に続く部分も、あなたの案の形で描く（今の HTML を流用してよい）。最初に出るページに今の 7 節の一部または全部を載せない案なら、`mockup.html` はそのページだけでよく、
     載せなかった節がどこから読めるかを `aim.md` の「今の 7 節」に 1 行ずつ書く（例：Projects → 今の /projects）。
     About（要点 3 つと外部リンク 3 つ）は今は詳しい版の HTML ページが無いので、載せないなら、どこで読めるようにするか（新しいページを作るなら URL と中身）を書く
   - 文章は `input/` にある実際のものを使う
   - 1280px と 375px の両方で崩れず、横スクロールしないこと。ライト・ダーク（`prefers-color-scheme`）の両方で読めること
   - ブラウザで表示を確かめられないときは、幅を %・`minmax()`・`max-width` で決め、375px より広い固定の幅や `white-space: nowrap` の長い文字列を使わない。
     どの幅・どの配色で確かめたか（確かめられなかったか）を `aim.md` の「あなたが判断したこと」に 1 行書く
   - 動きを入れるなら、開いてから 3 秒以内に終わり、終わった姿が案の姿になるようにする。動きの途中でも横にはみ出さない（画面の外から横に滑り込ませない。`overflow-x: hidden` で隠して済ませない）。
     `prefers-reduced-motion: reduce` のときは、動きの終わりの姿を最初から出す。繰り返し続く動きは、どの瞬間に止まっても読めるものだけにする。
     調整役は、開いて 4 秒待った姿と、reduce の姿を撮って比べる
2. `aim.md`：次の見出しをこの順に使う（案どうしを部分ごとに比べるため）

   ```markdown
   ## 狙い

   （3 行）

   ## 部分ごとの案

   - 構成：（トップの構成を変えるか、変えるならどう変えるか。1 行）
   - 最初の画面に置くもの（1280×800）：（上から順に、短く）
   - 最初の画面に置くもの（375×812）：（上から順に、短く。PC と同じなら「PC と同じ」）
   - 見た目：（文字の大きさ・余白・配置・線や地色の使い方で、今と変えたところ。1 行）
   - 動き：（「なし」か、「いつ〔開いたとき／スクロールしたとき／マウスを乗せたとき など〕・何が・どう動くか・CSS だけか JavaScript も使うか」。1 行）
   - 今の 7 節：（どこに置き、どう見せるか。1 行。最初に出るページに載せない節があれば、節ごとに 1 行ずつ、7 行まで）
   - 目次（PC の左・375px の上部）：（変えるか、どう変えるか。1 行）
   - 右下の Ask AI ボタン：（今のまま / 消す / 動かす。1 行）

   ## 変える決まり

   形は「見本の文 ← 元にした文（ファイル名）」。新しく書いた文は「見本の文 ← 新規」。なければ「なし」）
   ```

## 6. 守ること（変えられない枠）

- このサイトは Public。`input/` に無い事実・数字・実績・リンク（URL・メールアドレス・SNS のアカウント）を足さない。
  特に、家族・金銭・住所・年齢・転職活動の状況（「転職先を探しています」「Open to work」など）・企業名・現職の内部情報・人事評価・健康・連絡先は書かない
- 見本と `aim.md` に書くのは `input/` にあることだけ。この作業の前から知っていること（設定ファイルや会話に書かれた持ち主の情報を含む）は、`input/` に無ければ書かない
- グラデーション・光るカード・3D・ロゴの羅列は使わない（持ち主の発言のとおり。3 の決まりと違い、今回は変えられない）
- 作業フォルダの外に書き込まない。ネットワークを使わない
- 作業フォルダの外のファイルを読まない（`input/` はあなたの作業フォルダの中にある）
- 質問はできない前提で、分からないことはあなたの判断で決め、`aim.md` の「あなたが判断したこと」に書く
- 終わったら、最後の返答は「書いた」の 1 語だけにする（案の中身を要約しない）
