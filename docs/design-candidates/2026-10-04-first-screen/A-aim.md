## 狙い

開いた直後の 1 画面を本の「表紙」にし、名前・一言・要点 3 行・目次だけを置く。カードや一覧は、スクロールした先（表紙をめくった先）に回す。
目次を表紙の主役にして「どこに何があるか」を最初の画面で見せる。件数は本の目次の点線のように 1 件 1 マスで並べ、数字を読まなくても量が分かるようにする。
派手な飾りは足さない。大きな文字・余白・細い線と、開いたときに 1 回だけ線を引く動きで「整っている」印象を作る。

## 部分ごとの案

- 構成：1 枚のページのまま、先頭に画面 1 つ分の表紙を足す。左の固定目次（PC）は表紙の下から出て、そこから画面に貼り付く
- 最初の画面に置くもの（1280×800）：名前（大きく）→ 一言 → 左に要点 3 行（小見出し・太字の見出し・薄い補足）、右に目次 7 項目（番号・件数・1 件 1 マス）と GitHub・Qiita・llms.txt → 下端に ↓
- 最初の画面に置くもの（375×812）：名前 → 一言 → 要点 3 行（縦積み）→ 目次 7 項目（2 列）→ GitHub・Qiita・llms.txt → 下端に ↓
- 見た目：名前を 1.75rem → 4.5rem（375px は 2.4rem）。要点は PC の 3 列をやめて、線で区切った 3 行にする（左に小見出し）。目次は表紙の右に 1.2rem で置き、行の上下の線を要点 3 行の上下の線とそろえる。表紙には地色もカードも使わず、線だけで区切る
- 動き：開いたとき、要点と目次の線が左から引かれ、文字と目次の行が 10px 下から順に浮かび、件数のマスが左から現れる（1.7 秒で終わる）。目次にマウスを乗せたとき、行の右端に → が出る。どちらも CSS だけ。reduce では最初から終わりの姿
- 今の 7 節：7 節とも同じページに残す。About は、表紙（名前・一言・要点 3 行）と、表紙の直後に置く外部リンクのカード 3 枚に分ける。Projects〜Ask AI は今の HTML のまま、カードの下に続ける
- 目次（PC の左・375px の上部）：PC の左の固定目次は今のまま、表紙を過ぎてから現れる。表紙の中に大きい目次を別に置く。375px は表紙の中の目次（全 7 項目・2 列・隠さない）だけにし、表紙の下には出さない
- 右下の Ask AI ボタン：見た目と位置は今のまま。表紙では出さず、本文がスクロールで上がってくると一緒に下から入ってきて、今の位置（右下 16px）で止まる（CSS の sticky だけ。JavaScript は増やさない）

## 変える決まり

- 構成「1 枚のページ + 左の固定目次」：1 枚のページの先頭に表紙を足す。左の固定目次は表紙の下から出す（PC）
- トップの About の見せ方（2026-10-03 に選んだもの）：要点の 3 列を、PC では線で区切った 3 行にする（「小見出し → 太字の見出し → 薄い文字の補足」の 3 つは残す）。外部リンクのカード 3 列は形を変えず、表紙の直後に移す
- 375px の目次「上部に横並び」：ページ最上部（名前の上）から、表紙の中（要点 3 行の下）の 2 列に移す。全項目を出す・ボタンで隠さないは変えない
- PLAN.md「やらないこと」のアニメーション：開いたときの 1 回だけの動き（線を引く・文字が浮かぶ・件数のマスが現れる）と、目次にマウスを乗せたときの → を許す
- 図：目次の件数に、Articles の図と同じ「1 件 1 マス」の小さな図を足す（Projects・Systems・Articles の 3 行だけ。PC だけ）
- 本文幅「最大 52rem（左の目次 16rem を除く）」：表紙だけは左の目次が無いので、最大 68rem（16rem + 52rem）まで広げる

## 新しく書いた言葉・変えた言葉

- 01・02・03・04・05・06・07（表紙の目次の番号。読み上げない）← 新規
- 12 件（表紙の目次の Projects の件数）← 4 / 12 件（index.html の Projects の見出し）
- ↓（表紙の下端。読み上げない）← 新規
- →（表紙の目次にマウスを乗せたときに出る。読み上げない）← 新規

## あなたが判断したこと

- 要点 3 行の薄い補足（「継続的にコードを書く担当ではない」「React は学習中」など）は表紙に残した。太字の見出しだけだと「約 10 年」が書く経験に読めてしまい、根拠と区分を混ぜない方針からずれるため
- 外部リンクの補足文（「すべてのコードと設計判断（ADR）の一次情報」など）は表紙から外し、カードのまま表紙の直後に置いた。表紙には、今の左の目次の下にあるのと同じ GitHub・Qiita・llms.txt の文字リンクだけを置いた
- 件数を出したのは、今のトップに件数が書かれている 3 節だけ（Projects・Systems・Articles）。Projects は「4 / 12 件」のうち全体の 12 件を使った
- 表紙の高さは画面の高さ以上（100svh）。中身が入りきらない画面では表紙が下へ伸びる
- 375px の表紙の下には目次を出さない。表紙の中に同じ 7 項目があり、二重になるため。今も 375px の目次はスクロールに追従しないので、別の節へ移るときに上まで戻る手間は今と同じ
- 表紙の下の本文（カード・各節・最終確認日・フッター）は、今の HTML と CSS を写して使った。CSS で変えたのは、左の目次と本文の 2 列を body から表紙の下の箱に移したところだけ
- 確かめた幅と配色：Playwright（Chromium）で 1280×800 と 375×812 を、ライト・ダーク・reduce の 3 通りで撮った。どれも横スクロールなし（ページの幅＝画面の幅）。動きの途中（開いて 0.3 秒）でも横にはみ出さないことを確かめた
- 最初の画面の文字数（ブリーフと同じ数え方。空白を除く）は、1280×800・375×812 のどちらも 299 字だった（手元の Linux の書体での値。端末の書体で多少変わる）
- 書体は今の --font-sans / --font-mono のまま。手元の Linux の書体でしか見ていないので、Mac・Windows の書体での見え方は未確認
- 作業の始めにファイル一覧を見たとき、作業フォルダの 1 つ上にある調整役のファイル（check-mockup.mjs と makers.local.md）を開いてしまった。見本と aim.md の中身には使っていない
