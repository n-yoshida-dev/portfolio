## 3 サイトに共通していたこと（今のサイトに無いもの）

1. 見出しの下に段落を書かず、**ラベル + 値**の並びで見せる。年・数字・区分が左か右の定位置にある
2. 1 項目が短い（題名 + 一文）
3. **効かせる色が 1 つ**（tania は赤、koki は無彩色 + 等幅、okojomoeko は紫のタイムライン）

今のサイトは「H1 → 段落 → H2 → 段落 or 表」の技術文書型で、ラベルが無く、数字が文中に埋まっている。
これが「ウィキペディアみたい」「上から読まないと分からない」の正体だと見ている。

## Claude の推し

**C を推す。** 理由は 2 つ。
ユーザーの不満は「どこに何が書いてあるか構造として分かりづらい」で、C は数字タイルとカードの枠で「項目の境界」と「数字」が最初の 1 画面に出る。
「好き」と答えた 3 件のうち 2 件（tania のカード、okojomoeko の Projects カード）がカードを使っている。
代償は SPEC §4「カード UI にしない」の撤回。ただし PLAN「派手な見た目はやらない」の中身（グラデーション・光るカード・3D・アニメーション）には触れず、薄枠と地色だけで済む。

SPEC §4 を変えたくなければ **A** が次点。サイドバーの目次が常に見えるので「どこに何があるか」は解決し、色を 1 つ足すだけで済む。
B は今の延長で、そっけなさは残る。
