# ブリーフ：ポートフォリオのトップの節の見せ方

このブリーフは同じ内容で 3 者に渡しています。お互いの案は見えません。あなたの案を 1 つだけ作ってください。

## 1. このサイトは何か

Naoki Yoshida の個人ポートフォリオサイト（公開中。Astro の静的サイト、素の CSS 1 ファイル）。
自作アプリの一覧と、AI・GitHub・自作ツールを組み合わせた開発・学習の仕組みを公開している。
トップは 1 枚のページに 7 節（About / Projects / Systems / Skills / Journey / Articles / Ask AI）を縦に並べ、左の固定目次で節へ移動する。
各節は短い版で、詳しい版は各ページ（/skills、/journey、/articles など）にあり、「すべて →」などのリンクで行く。

### 誰のためのものか（サイトの計画書 PLAN.md の原文）

1. **転職の選考で見る人**：短時間で「何の人か」「何を作ったか」「どう開発しているか」を把握したい
2. **AI**：訪問者の ChatGPT / Claude / Gemini が、私について根拠付きで答えられるようにする（`/llms.txt`、Markdown 版、Ask AI）
3. **自分**：分散した成果物の索引。将来は skill-matrix から Skills を自動生成する土台

## 2. 頼みたいこと

トップのうち **About（箇条書きとリンク）・Skills・Journey・Articles の 4 節の見せ方** を変える案を 1 つ作ってください。
Projects / Systems / Ask AI の節は対象外です（今の形のまま描いてかまいません）。

サイトの持ち主が本番のトップを見て言ったこと（原文。2026-10-02）：

- 「Aboutの章がパッとしないな。箇条書きだけだからかな。」
- 「GitHub、Qiita、Reading Logのリンクがあるけど、なんかパッとしないな。文字だけだとわかりづらいというか。。絵が無いからか？」
- 「Skillsのところ、文字だけだとわかりづらいか。」
- 「Journeyは詳細開くと見やすいんだけど、トップ画面だと見辛いな。これも文字だけだからか？」
- 「Articlesは、トップ画面では分類ごとの記事数を書いてるんだよね？ただ、これ初見だとなんのことかわからん。」

補足の事実：

- 「Skillsのところ」がトップの節を指すか `/skills` のページを指すかは、持ち主に確認していない。`/skills` のページ（区分ごとのカード）には 2026-09-29 に持ち主が「いい感じ。」と言っている
- 持ち主はこのサイト全体を「今、いまいちな状態」と言っている
- 文面（言葉）を直すタスクは別にある（About の箇条書きの書き方など）。この案は **見せ方** の案で、文面は今の公開プロフィールのものを使ってよい。言葉を短くする・並べ替えるのはかまわないが、事実・数字・実績を足さない

## 3. 今の決まり（変えてもよいが、変えるなら明示する）

次の決まりは、これまで持ち主と合意して決めたもの。今回のタスクの完了条件には「PLAN〔やらないこと〕・SPEC §4〔色・影など〕を変えるならその変更も含む」とあり、変えることは禁止されていない。
変える案なら、どれをどう変えるかを `aim.md` に書くこと。

- PLAN.md「やらないこと」：派手な見た目（グラデーション、光るカード、3D、アニメーション、ロゴの羅列）。薄枠のカードと左の固定目次は 2026-09-27 に許容した
- 色は文字・薄い文字・線・リンク・背景（地色 `--bg-subtle` を含む）の 5 系統。ダークモードは OS 設定に追従
- 青はリンク専用（例外：Journey の年表の点は青）。ボタンは青を使わず文字色で描く。塗るのは主なボタンと右下の追従ボタンだけ。角は 4px
- 一覧は薄枠のカード（地色 `--bg-subtle`、線 `--line`。PC 2 列、375px で 1 列）。グラデーション・影・アニメーションは使わない。色は足さず、リンク色だけを効かせる
- トップの最初の 1 画面に、名前 + 一言 + 要点 3 行 + 目次が入る
- 375px 幅では目次の全項目を上部に横並びで出す（ボタンで隠さない）
- JavaScript は Ask AI のコピーと目次のスクロール監視だけ。ライブラリを増やさない
- 本文幅は最大 52rem（左の目次 16rem を除く）、モバイルは左右 16px の余白。横スクロールさせない
- HTML は人間向けに短く、Markdown 版・llms.txt は AI 向けに詳しく
- このサイトは Public。公開プロフィールにある情報以外（勤め先の名前、家族、非公開リポジトリの中身など）を書かない

## 4. 渡すもの（このフォルダの `input/`）

- `input/shots/`：本番と同じビルドのトップ。`top-1280-first.png`（1280×800 の最初の画面）、`top-1280-full.png`（全体）、`top-375-first.png`、`top-375-full.png`。
  全体図の途中に写る黒いボタンは右下の追従ボタン（画面に固定）で、全体を撮ったために途中に写っている
- `input/site/index.html` と `input/site/global.css`：今のトップの HTML と CSS（ブラウザで開ける）
- `input/public-profile/`：サイトの文章の正本（Markdown / JSON）。トップの各節はここから作られている

## 5. 作るもの（あなたの作業フォルダの直下に置く）

1. `mockup.html`：案を描いた見本 1 枚
   - 1 ファイルで完結させる（CSS は中に書く。外部の画像・フォント・スクリプトを読まない。絵が要るならインライン SVG か CSS で描く）
   - トップ全体（左の目次と 7 節）を、あなたの案の形で描く。文章は `input/` にある実際のものを使う
   - 1280px と 375px の両方で崩れず、横スクロールしないこと
2. `aim.md`：狙いを 3 行。3 の決まりを変える案なら、その下に「変える決まり：」として 1〜3 行

## 6. 守ること

- 作業フォルダの外に書き込まない。ネットワークを使わない
- 作業フォルダの外のファイルを読まない（`input/` はあなたの作業フォルダの中にある）
- 質問はできない前提で、分からないことはあなたの判断で決め、その判断を `aim.md` の末尾に 1 行で書く
