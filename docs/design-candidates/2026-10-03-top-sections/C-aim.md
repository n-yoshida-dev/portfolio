# 狙い

1. About：箇条書きをやめて「仕事・個人開発・進め方」の 3 列（小見出し＋太字の一文＋補足）に組み替え、GitHub / Qiita / Reading Log は「線アイコン・名前・そこに何があるかの一言・行き先」を持つカードにして、文字だけのリンクをなくす。
2. Skills・Journey：持ち主が「いい感じ」と言った /skills の区分カードの形をトップでも使い（項目はタグ、実装の根拠がまだない区分は破線の枠）、Journey は詳細ページで見やすいと言われた「線と青い点」の年表を PC では横向きにして、10 年の移り変わりを一目で見せる。
3. Articles：「分類名と本数」だけの並びをやめ、先に「Qiita に 21 本、■ 1 つが 1 本」と言ってから連載 × 公開月の図で並べる。連載が左上から右下へ階段状に進むので、何の数かと学んだ順が説明なしで読める。最新の 1 本は題名で見せる。

変える決まり：
- 列数：About の要点 3 つとリンク 3 つは PC で 3 列にする（「一覧は PC 2 列」の例外。375px は 1 列のまま。Skills は 2 列＋全幅 1 枚で今の決まりの内）
- 絵：ロゴではない単色の線アイコン（薄い文字色）を About のリンクと Skills の区分見出しにだけ使う。Articles の図は薄い文字色の四角、About の要点の縦線は文字色で描き、色は足さない（青はリンクと年表の点だけのまま。図はビルド時に articles.json から作り、実行時の JavaScript は増やさない）
- カード：Skills の「理解確認済み・学習中」だけ破線の枠・地色なしにする（「薄枠＋地色」の例外）。トップの Journey にも青い点を使う（「年表の点は青」の例外の範囲内と解釈）

判断：「Skillsのところ」はトップの節を指すと解釈して /skills のカードの形をトップに寄せ、文面は public-profile にある言葉（profile.md の links の note、skills.md の区分の定義、career.md の経歴、articles.json の連載と公開日）だけを短くして使い、事実・数字は足していない。
