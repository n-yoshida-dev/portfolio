# 狙い

- 色や絵を足さずに「形」で読ませる。About の要点 3 行は profile.md の見出しそのまま「何の人か / 何を作っているか / どういう開発スタイルか」の 3 枠に、Skills は区分ごとのカード 3 枚 + 短いチップに、Journey は点線でつないだ横の年表（375px では縦）に、Articles は「1 マス = 1 本」のタイル + 連載ごとの最新記事 1 本に置き換えた
- 「何を見ているか」を各節の見出し直下に 1 行で言う（Skills「区分は混ぜません」、Journey「会社名は書かず、役割の変遷だけ」、Articles「連載ごとの本数です。1 マス = 1 本」）。特に Articles の「初見でなんのことかわからん」は、数字の意味と中身（題名）が見えないのが原因と判断した
- GitHub / Qiita / Reading Log はブランドロゴではなく線画の汎用アイコン（コード・ペン・本）付きのカードにし、profile.md の `links[].note`（そこに何があるか）を添える。使う色は既存の 5 系統のまま（線画は currentColor、タイルとカードは `--bg-subtle` + `--line`、年表の点は既存の例外どおり青）

変える決まり：
- 「一覧は薄枠のカード PC 2 列」→ Skills のカードと About のリンクカードは PC 3 列（区分・リンクが 3 つのため。375px では 1 列）
- 「HTML は人間向けに短く」の範囲内だが、Journey に各期の主な担当（career.md の表の 3 列目を短縮）、Articles に連載ごとの最新記事の題名 1 本、About に各リンクの note を足したぶん、HTML はやや長くなる。いずれも public-profile にある文言で、事実・数字は足していない

判断したこと：「Skills のところ」はトップの節を指すと解釈し（/skills には「いい感じ」の評価があるため）、/skills のカード構成をトップ向けに短くした形で揃えた。確認用のスクリプトと画像は `check/` にある。
