# 判断ログ

議論で到達した判断と、その理由・却下した代替案の台帳。
同じ論点を後で蒸し返さないために残す。新しいものほど上にある。

ここに書くのは**ユーザーと合意した判断**（方針・スコープ・生活の前提・複数案から選んだ設計）。
Claude が実装中に選んだ技術的な選択とハマりどころは `KNOWLEDGE.md`。やることは `TODO.md`。
追記は `/decide`。新しいエントリは下の `---` の直後に入れる（`/decide` がそうする）。

1 エントリの形式（`/decide` と同じ。1 エントリ 1 判断）：

```
## YYYY-MM-DD <論点を一言で>

**論点**: 何を決めようとしていたか
**結論**: どう決めたか
**理由**: なぜその結論にしたか
**却下した代替案**: 検討して捨てた選択肢と、捨てた理由（なければ「なし」）
**確信度**: 高 / 中 / 低
**見直す条件**: この前提が崩れたら判断をやり直す、という条件（なければ「なし」）
```

## 2026-09-27 ボタンは青の塗りをやめ、文字色で描く（塗るのは主なボタンと右下の追従ボタンだけ）

**論点**: ボタン（トップの Ask AI 節・右下の追従ボタン・`/ask` のコピーと各 AI で開く）の見た目。ユーザーの発言は「なんかボタンのデザインとかがブートストラップっぽいけど、これらも後から直されるの？」

## 2026-09-27 デザインの方向は「1 枚のページ + 左の目次」に、A 案の年表と C 案のカードを組み合わせる

**論点**: フェーズ3「デザインの見直し」で、見本 3 案（A 年表・定位置 / B 索引・等幅 / C カード・数字。`docs/design-candidates/README.md`）のどれを採るか。左のタブは「ページを切り替える」か「1 枚のページの中を移動する目次」か
**結論**: A と C の組み合わせ。左に固定の目次（A）、経歴は年表（A）、プロジェクトは薄枠のカード（C）。
**トップを 1 枚のページ**にして「何の人か → Projects → Systems → Skills → Journey → Articles → Ask AI」を節として縦に並べ、左の目次はその節へ移動する（brittanychiang 型）。
1 枚のページには各節の**短い版**（主なプロジェクト 4 件のカード、区分ごとの項目名だけのスキル、年表）を置き、詳しい版は今の各ページに残して「すべて →」で行く（深さの段階化）。
色は足さない。C 案のオレンジ系は使わず、今のリンク色（青）だけを効かせる。カードの地色と線は今の `--bg-subtle` / `--line` を使う。
SPEC §4 の「カード UI にしない」は撤回する（薄枠 + 地色まで。影・グラデーション・アニメーションは引き続きなし）。
目次の「今いる節」を示すスクロール監視の JavaScript（15 行ほど）は足してよい。理由は `KNOWLEDGE.md` に書く
**理由**: ユーザーの不満は「どこに何が書いてあるか構造として分かりづらい。上から読まないと分からない」。1 枚に全体像を並べて左の目次で現在地と行き先を常に見せると、これに直接効く。
